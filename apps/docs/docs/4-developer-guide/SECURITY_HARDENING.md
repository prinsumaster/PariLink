# Security Hardening Guide (GA)

## 1. API Security
- **Authentication**: JWTs are utilized with strict 1-hour expiration. A distinct `Refresh Token` system is implemented (7-day expiry, stored securely, rotatable on logout).
- **Rate Limiting**: NestJS `@nestjs/throttler` is bound globally (limit: 10,000 requests / minute) to prevent Brute Force and DDoS. Critical endpoints like login are throttled to 5 requests / minute per IP.
- **Helmet**: `@nestjs/helmet` is enabled to enforce strict CSP, HSTS, X-Frame-Options, and XSS Protection headers.
- **CORS**: Strictly configured to only allow requests from `https://app.parilink.com`.
- **Validation**: Strict `ValidationPipe` with `whitelist: true` and `forbidNonWhitelisted: true` to prevent mass-assignment attacks (e.g., stripping injected `companyId` parameters).

## 2. Container Security
- **Non-Root User**: The production Dockerfiles define a `nodejs` group and a `nestjs`/`nextjs` user with UID 1001. The containers run entirely in non-root mode.
- **Minimal Surface**: Based on `node:18-alpine` which drastically reduces the attack surface compared to full Debian images.
- **Scanning**: Trivy is enforced in the CI pipeline to block any image with Critical or High OS vulnerabilities.

## 3. Multi-Tenant Data Security
- **Prisma Extension Contexts**: Cross-tenant data leakage (BOLA/IDOR) is prevented natively at the ORM layer. The database is partitioned using Postgres configuration variables (`set_config('app.current_tenant', ...)`).
- **Row Level Security (RLS)**: PostgreSQL enforces that any query inherently limits its scope to `company_id = current_setting('app.current_tenant')`.

## 4. Dependency Auditing
- **SBOM**: A Software Bill of Materials is automatically generated by Anchore upon every push to `main` for licensing and compliance audits.
- **npm audit**: Pipeline enforces a block on High/Critical CVEs within Javascript dependencies.
